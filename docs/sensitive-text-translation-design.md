# تصميم مقترح لترجمة أسباب الإجازات والنصوص الحساسة

هذه وثيقة تصميم، وليست ميزة جاهزة. لم تُطبَّق أي تغييرات على قاعدة البيانات، ولا يوجد حتى الآن مسار آمن في التطبيق يترجم هذه النصوص أو يحفظ ترجماتها. الترجمة الحالية الخاصة بأسماء العمال لا تشمل أسباب الإجازات أو الملاحظات.

## النطاق الأولي

حقل سبب طلب الإجازة `requests.reason` للطلبات ذات `leaveKind` فقط. قد يتضمن بيانات صحية؛ لذلك لا يفعّل إعداد ترجمة الأسماء ترجمة هذا الحقل، ولا تُرسل أسبابه إلى موفر خارجي إلا بعد تهيئة مستقلة وصريحة. لا يعالج هذا المقترح أسباب القرار أو سجلات التدقيق أو ملاحظات الحضور، ويجب ألا تُعرض على أنها مغطاة.

## خطة إضافة جدول مستقل

لا يُستخدم جدول `translations` الحالي للنصوص الحساسة؛ واجهته الحالية تقرأ على أساس اسم الحقل فقط ولا تتحقق من صلاحية السجل. بعد مراجعة المخطط واختباره على قاعدة معزولة، يمكن إضافة جدول جديد، مثل المثال التالي، عبر أداة migrations المعتمدة في المشروع. **المثال أدناه للتصميم فقط ولا يُنفَّذ تلقائيًا:**

```sql
CREATE TABLE protected_text_translations (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  entityType VARCHAR(60) NOT NULL,
  entityId INT NOT NULL,
  fieldName VARCHAR(60) NOT NULL,
  language ENUM('ar', 'en', 'ur') NOT NULL,
  sourceLanguage ENUM('ar', 'en', 'ur') NOT NULL,
  sourceHash CHAR(64) CHARACTER SET ascii NOT NULL,
  translatedText TEXT NOT NULL,
  origin ENUM('automatic', 'manual') NOT NULL,
  reviewStatus ENUM('unreviewed', 'reviewed') NOT NULL DEFAULT 'unreviewed',
  reviewedBy INT NULL,
  reviewedAt TIMESTAMP NULL,
  createdAt TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY protected_translation_unique (entityType, entityId, fieldName, language),
  KEY protected_translation_entity (entityType, entityId)
) CHARACTER SET utf8mb4;
```

الترحيل يضيف الجدول فقط، دون نقل أو تعديل النصوص الأصلية. يجب تثبيت توافقه مع إصدار TiDB وطريقة الترحيل بالمشروع قبل اعتماده. لا يمثل المفتاح المركب بديلًا عن فحص صلاحية الوصول. يلزم تحديد سلوك حذف السجل الأصلي وحذف ترجماته ضمن سياسة الاحتفاظ قبل التشغيل؛ المفتاح هنا متعدد أنواع السجلات ولا يحميه مفتاح أجنبي واحد.

## قواعد القراءة والصلاحية

1. تعتمد الخدمة نوع السجل والحقل من قائمة ثابتة في الخادم، وليس من اسم يرسله المتصفح دون تحقق. في المرحلة الأولى القيمة المسموحة هي طلب الإجازة وحقل السبب فقط.
2. تتحقق أولًا من صلاحية `leave:read` ومن نطاق العامل خلال فترة الإجازة، وفق قواعد `listLeaves` الحالية. يمنع أي رد يضم السبب أو ترجمته إذا لم تنطبق الصلاحية والنطاق؛ ولا يُسمح بقراءة الترجمات عبر مسار `translations.getTranslations` القديم.
3. تقرأ السبب الأصلي من طلب الإجازة المخول نفسه. تُعرض الترجمة فقط إذا تطابق `sourceHash` مع بصمة النص الحالي ولغة الهدف؛ وإلا يظهر الأصل مع بيان أن الترجمة بحاجة إلى تحديث أو مراجعة.
4. يمنع إدراج النص أو بصمته أو مفتاح الموفر في سجلات الأخطاء أو روابط المتصفح. تخضع الترجمة لنفس خصوصية النص الأصلي.

## الحفظ والتحديث وحماية التصحيح البشري

1. يُحفظ السبب الأصلي كما هو مع طلب الإجازة. يُحدد المستخدم اللغة الأصلية صراحةً؛ لا يُعتمد على لغة واجهته وحدها لاستنتاج لغة النص.
2. تجرى استدعاءات الترجمة خارج معاملة قاعدة البيانات، مع وقت انتظار محدد. لا يؤدي فشلها إلى فشل حفظ طلب الإجازة ولا تُعرض نتيجة قديمة بوصفها حديثة.
3. بعد استلام الترجمة تبدأ معاملة تقفل صف الطلب، وتتحقق مجددًا من النص والبصمة ومن أن العامل والفترة لم يتغيرا، ثم تقفل أو تنشئ صف الترجمة. تُرفض النتيجة إذا تغير المصدر أثناء الاستدعاء.
4. يمنع التحديث الآلي استبدال ترجمة ذات `origin=manual` أو `reviewStatus=reviewed`. عند تغيير الأصل، تبقى النسخة البشرية محفوظة، وتُعلَّم على أنها تحتاج مراجعة لأن بصمتها لا تطابق النص الجديد، بدل إتلافها أو عرضها بوصفها ترجمة حالية.
5. يجب أن تحفظ تغييرات المصدر والترجمة البشرية بمسارات تستخدم الأقفال نفسها، مع سجل تدقيق للتعديل والصلاحيات المناسبة. يقتصر تعديل الترجمة البشرية مبدئيًا على من يملك صلاحية اعتماد الإجازة ونطاق العامل، بعد اعتماد هذا القرار وظيفيًا.
6. تكون الحالة الظاهرة «بانتظار الترجمة» أو «تحتاج مراجعة» أو «تعذرت الترجمة» عند الاقتضاء. إعادة المحاولة عمل مستقل ومحدود؛ لا تكشف الأخطاء تفاصيل طبية أو بيانات اعتماد.

## التحقق قبل الدمج

- اختبار الترحيل والاستعلامات على قاعدة مستقلة، بما في ذلك تزامن تعديل الأصل مع رد الموفر وتزامن التصحيح البشري مع التحديث الآلي.
- اختبار منع الوصول لمستخدم خارج النطاق ومن لا يملك `leave:read`، بما في ذلك تغيير نطاق العامل أو فترة الإجازة أثناء تشغيل الطلب.
- اختبار فشل الموفر، وإعادة المحاولة، والنصوص الطويلة، واللغات الثلاث، وعدم عرض ترجمة لبصمة قديمة.
- اختبار التعديل اليدوي والمراجعة، والحذف وسياسة الاحتفاظ، ثم اختبار الواجهة دون إرسال بيانات موظفين حقيقية في التجربة.
- الإبقاء على الميزة الحساسة معطلة عند غياب الإعداد أو الجدول، وإتاحة إيقافها دون حذف الأصل أو الترجمات المحفوظة.
