## 1. المعمارية (منجز بالكامل ✅)

- **Backend:** Modular Clean Architecture — كل دومين في `server/modules/<name>/` بثلاث طبقات (router → service → repository)
- **Frontend:** بداية فصل `client/src/features/` حسب الدومين (attendance, auth, ai-assistant)
- **التوثيق:** `ARCHITECTURE.md` (قواعد المعمارية) و`MODULES.md` (فهرس الوحدات) موجودان بجذر المشروع — راجعهما قبل أي تعديل هيكلي
- **الوحدة المرجعية الكاملة:** `server/modules/attendance/` (router+service+repository+اختبارات) — انسخ نمطها لأي وحدة جديدة

## 2. المصادقة (منجز بالكامل ✅)

- ألغيت مصادقة Manus OAuth بالكامل، واستُبدلت بنظام محلي: بريد + كلمة مرور + جلسات JWT (كوكي httpOnly)
- `server/modules/auth/` فيه: `auth.service.ts` (bcrypt+JWT)، `auth.router.ts` (login/me/logout/register)
- إنشاء الحسابات محمي بصلاحية `USERS_CREATE` (لا تسجيل ذاتي مفتوح)
- أول مسؤول يُنشأ عبر: `ADMIN_EMAIL=... ADMIN_PASSWORD=... pnpm seed:admin`
- صفحة `/login` جاهزة، وصفحة `/` (الجذر) تُوجّه تلقائيًا حسب حالة الجلسة

## 3. التشغيل المحلي (منجز بالكامل ✅)

- `pnpm dev` يعمل الآن على ويندوز/ماك/لينكس بدون فرق (أُصلحت مشكلة `NODE_ENV` عبر `cross-env`)
- خطوات التشغيل الكاملة موثقة في `ARCHITECTURE.md` تحت "خطوات التشغيل الأول"

## 4. نتيجة تحليل الفجوة (BA/PM) — آخر قياس

قارنّا وثيقتي الخطة (الخطة الشاملة + خطة محرك الترجمة) مع الكود الفعلي:

| الوثيقة | نسبة الإنجاز |
|---|---|
| الخطة الشاملة للمنصة | ≈ 35–40% |
| خطة محرك الترجمة | ≈ 15–20% |

**ملاحظة:** هذا القياس **قبل** إضافة المصادقة المحلية — يحتاج تحديث لو أردنا رقمًا دقيقًا الآن (المصادقة كانت خارج نطاق الخطة أصلًا فما تغيّر الرقم كثيرًا، لكن يستحق إعادة حساب لاحقًا).

### أخطر 3 فجوات لم تُحل بعد 🔴
1. **المعادلات المالية المعتمدة (صفر من خمس منفذة بشكل صحيح):**
   - الإضافي مبرمج كرقم ثابت (`hours × 1.5`) بدل معادلة الخطة (شامل÷معياري + 50% من أساسي÷معياري)
   - لا وجود لقاسم 234، فئات الحافز 200–450، شرائح الصرف 0/50/75/100%
   - سقف 66% لحوافز المحلات غير موجود
   - قواعد خصومات الكاشيرات (15%/20%، خصم الغياب 10%) غير موجودة
2. **18 من 22 صفحة واجهة تعرض بيانات ثابتة (Placeholder)** وليست مربوطة بالـ API الفعلي — فقط الحضور وتسجيل الدخول مربوطتان حقًا
3. **جداول قاعدة بيانات كاملة غير موجودة:** Store, StoreRevenue, CashierSales, ShortageRecord (حوافز المطاعم والكاشيرات بلا أساس تخزين)

### فجوات أخرى مهمة
- `workers` CRUD في الـ Backend عبارة عن placeholders (`return {success:true}` بدون إدخال فعلي بقاعدة البيانات)
- لا يوجد جدول Assignments/Reservations ولا محرك تحقق (منع تعارض جدولة عامل في إجازة)
- محرك التقييم: لا يوجد حساب أوزان فعلي، ولا نسخ تلقائي لآخر تقييم، ولا تجميع أسبوعي/شهري
- محرك الترجمة: جدول `translations` مبسّط جدًا، لا يوجد `translation_jobs`، لا سياسة Fallback، لا شاشة مراجعة بشرية
- الذكاء الاصطناعي: `ai-assistant` موجود كـ "chat عام" بخمس وظائف، لكن بدون بوابة أدوات مسماة أو مستويات صلاحية (0-4) كما تصف الخطة
- **خطأ صامت مكتشف:** أسماء الأدوار في القائمة الجانبية (`finance_reviewer`, `accountant`, `auditor`) لا تطابق قاعدة البيانات (`financial_reviewer`, `accounting_head`) — يعني المراجع المالي ورئيس الحسابات لن يروا عناصر القائمة الصحيحة عند تسجيل الدخول

## 5. خارطة الطريق المتفق عليها (لم يُنفذ منها شيء بعد)

مرتبة بالاعتماديات — كل مرحلة تبني على اللي قبلها:

| المرحلة | المحتوى |
|---|---|
| **أ** | إكمال workers CRUD الفعلي + APIs التقويم/الرواتب + ربط WorkerHub ببيانات حقيقية + جداول المطاعم/الكاشيرات + **إصلاح تطابق أسماء الأدوار (عاجل، لا يحتمل التأجيل)** |
| **ب** | محرك التحقق (منع تعارض/تجاوز حد) + جدول Assignments + شاشة توزيع العمال الذكية |
| **ج** | محرك التقييم الفعلي (أوزان، نسخ تلقائي، تجميع، ترتيب وألوان) + seeding نماذج الأقسام الأربعة |
| **د** | محركات الحوافز والإضافي بالمعادلات الصحيحة (÷234، شرائح، سقف 66%، خصومات الكاشيرات) — **مع اختبار وحدة لكل معادلة بأمثلة الخطة نفسها** |
| **هـ** | الدورة الشهرية كاملة (تشغيل المحركات داخل الفترة) + ربط التقارير واللوحات بالـ API |
| **و** | ترقية محرك الترجمة (جدول translation_jobs، إعادة المحاولة، القاموس، شاشة المراجعة) |
| **ز** | ترقية الذكاء الاصطناعي (بوابة أدوات مسماة، مستويات صلاحية 0-4) |

## 6. التصميم (Design System)

- تم الاتفاق على هوية بصرية: **داكن افتراضي** (مع تبديل لفاتح)، **كحلي كأساسي + لمسة تركوازي مطفأ** في العناصر النشطة، خط IBM Plex Sans Arabic + IBM Plex Mono للأرقام، عنصر توقيعي "شريط اليوم الوظيفي" (04:30→04:29)
- **نموذج تجريبي منفّذ ومعتمد شكليًا** على صفحتين (Dashboard + جدول الحضور) كملفات HTML مستقلة — **لم يُدمج بعد بالكود الفعلي للمشروع** (لسه بانتظار التعميم على باقي الصفحات)
