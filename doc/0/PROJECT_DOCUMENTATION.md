---

## 1. هدف الوثيقة

هذه الوثيقة هي المرجع المركزي للمشروع، ويجب قراءتها قبل تنفيذ أي تعديل.

أهدافها:

1. توثيق كل تعديل أو إضافة وسببها.
2. منع تكرار عمل سبق إنجازه.
3. منع إعادة مشكلة سبق إصلاحها.
4. منع تغيير قرار أو ملف معتمد دون استشارة صاحب المشروع.
5. توثيق المشكلات وأسبابها والحلول المعتمدة.
6. تحديد ما تم إنجازه وما لم يتم إنجازه.
7. تحديد ترتيب التنفيذ الإلزامي.
8. توثيق نسبة الإنجاز العامة ونسبة كل مرحلة.
9. الفصل بين وجود صفحة وبين اكتمال الوحدة وظيفيًا.
10. إنشاء سجل قرارات يمكن الرجوع إليه مستقبلًا.

---

## 2. قاعدة الحوكمة الإلزامية

### 2.1 قبل تنفيذ أي تعديل

يجب:

1. قراءة هذه الوثيقة.
2. التحقق هل المهمة سبق تنفيذها.
3. التحقق هل الملف سبق اعتماده.
4. تحديد سبب التعديل.
5. تحديد الملفات والجداول وواجهات API المتأثرة.
6. تحديد المخاطر والآثار الجانبية.
7. الحصول على موافقة صاحب المشروع عند وجود تغيير جوهري.
8. تنفيذ التعديل.
9. تشغيل الفحص والبناء والاختبار.
10. تحديث هذه الوثيقة.

### 2.2 ممنوع دون موافقة صاحب المشروع

- تغيير مخطط قاعدة البيانات.
- حذف جدول أو حقل.
- حذف أو تغيير API.
- تغيير مسار صفحة.
- تغيير دور أو صلاحية.
- تغيير معادلة مالية.
- تغيير قاعدة حافز أو إضافي أو خصم.
- تغيير دورة اعتماد أو إقفال.
- إعادة تصميم صفحة معتمدة.
- استبدال حل اجتاز الفحص والبناء.
- حذف وظيفة قائمة لأجل تحسين بصري.
- إضافة مكتبة أو مزود خارجي.
- إدخال بيانات تجريبية على أنها بيانات حقيقية.
- العمل على مرحلة غير المرحلة النشطة.
- جعل الذكاء الاصطناعي يصدر قرارًا ماليًا أو إداريًا نهائيًا.
- ربط الذكاء الاصطناعي مباشرة بقاعدة البيانات.

### 2.3 الاستثناء العاجل

يجوز تنفيذ إصلاح عاجل دون انتظار الموافقة فقط عند:

- فشل بناء كامل.
- ثغرة أمنية مؤكدة.
- خطر فقد بيانات.
- تعطل يمنع تشغيل النظام.
- تعطل يمنع استكمال المرحلة النشطة.

ويجب توثيق الإصلاح فورًا بعد تنفيذه.
