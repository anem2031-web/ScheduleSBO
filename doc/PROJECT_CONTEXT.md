## 2. هدف المشروع

الهدف هو تحويل العمليات التشغيلية من ملفات وجداول منفصلة إلى دورة مترابطة وقابلة للتتبع:

```text
العامل
↓
الجدول والوردية
↓
الحضور الفعلي
↓
رصيد الساعات
↓
التقييم
↓
الحافز أو الدوام الإضافي
↓
المراجعة والاعتماد
↓
الإقفال والتقارير
```

يجب أن تكون كل عملية حساسة قابلة للتتبع إلى:

- العامل.
- المصدر.
- التاريخ والوقت.
- المستخدم المنفذ.
- القاعدة المستخدمة.
- القيم السابقة.
- القيم الجديدة.
- سبب التعديل.
- المرجع أو المرفق عند الحاجة.

## 4. النمط المفضل لوحدات الخادم

عند إنشاء أو إعادة تنظيم وحدة في الخادم يفضل استخدام الهيكل التالي:

```text

├── <module>.router.ts
├── <module>.service.ts
├── <module>.repository.ts
├── <module>.validation.ts
├── <module>.types.ts
└── <module>.test.ts
```

- استقبال الطلب.
- التحقق من المدخلات.
- التحقق من هوية المستخدم.
- التحقق من الصلاحية.
- استدعاء Service.
- تحويل أخطاء الدومين إلى أخطاء API واضحة.
- عدم وضع منطق أعمال معقد داخله.

### مسؤولية Service

- تنفيذ منطق الأعمال.
- تطبيق القواعد.
- تنسيق العمليات المركبة.
- إدارة Transaction عند الحاجة.
- التحقق من الحالات والانتقالات.
- إنشاء أحداث التدقيق.
- إعادة نتائج واضحة وقابلة للاختبار.

### مسؤولية Repository

- التعامل مع قاعدة البيانات.
- تنفيذ الاستعلامات.
- تنفيذ عمليات الإدخال والتحديث والقراءة.
- عدم وضع قواعد أعمال رئيسية داخله.
- عدم اتخاذ قرارات صلاحيات داخله.

### مسؤولية Validation

- تعريف مخططات Zod.
- التحقق من حدود البيانات.
- التحقق من التواريخ والقيم.
- فصل أنواع مدخلات API عن أنواع التخزين عند الحاجة.
- إعادة رسائل أخطاء واضحة.

### مسؤولية Types

- الأنواع المشتركة داخل الوحدة.
- أنواع الدومين.
- أكواد الأخطاء.
- حالات الكيانات.
- عقود النتائج الداخلية.
